00 / Direction

Olive is a framework, not only a product suite.

Olive is a token adoption, security and interoperability framework. The framework is the foundation. The existing product experiences remain part of the ecosystem.

OLV is the native platform token. External assets are adopted under integration-specific terms and represented separately. CLV → OCLV is a 1:1 bridge; OCLV → OLV is a fixed swap. A representation is not OLV and is not cross-chain by default.

Framework first. Product experiences remain. Claims must match the implementation.

01 / Security

Security and operational readiness — Gate 0

Make the security proposition real through controls, evidence and operating discipline.

  • Key management and signing authority
  • Access control and approval thresholds
  • Deposit verification and duplicate prevention
  • Issuance and reconciliation controls
  • Monitoring, alerts and incident response
  • Emergency restrictions and review

Olive does not claim that the framework is trustless, risk-free, fully backed or audited. Disclosure follows evidence.

Security starts first and remains a gate. No real custody or representation issuance proceeds until the controls for that phase are approved and evidenced.

02 / Foundations

Framework foundations and architecture

Define the three-role model, asset taxonomy, custody responsibilities, verification boundaries, accounting model, claim rules and public terminology.

  • OLV and asset role definitions
  • Asset role taxonomy
  • Custody and control responsibilities
  • Verification and reconciliation model
  • Issuance and redemption boundaries
  • Claim matrix and disclosure rules

Current: public framework pages, glossary, audit and decision register are live. Planned: revised framework whitepaper.

03 / Asset adoption

Asset adoption and custody

Establish an external asset as an adopted asset under an approved integration, with its own custody arrangement and verification process.

  • Integration registry and supported routes
  • Custody control evidence
  • Network, asset and route validation
  • Deposit evidence and review
  • Reconciliation between custody and representation
  • Public integration terms

Current: CLV is live on Ethereum and BNB Smart Chain with network-specific bridge addresses. Confirm: public custody attestation, external review and proof standard.

04 / Representation

Representation, issuance and accounting

Represent an adopted asset inside Olive under integration-specific issuance, accounting and disclosure rules.

  • Representation standard
  • Issuance authority and idempotency
  • Balance and liability accounting
  • Reserve and reconciliation model
  • Transferability and product access
  • Redemption only if approved

Current: OCLV is live as the CLV representation at 1:1. OCLV is not listed on Trade; it can only be swapped to OLV through the approved pair when enabled. Open: backing/reserve treatment, redemption, external transfer and on-chain status.

05 / Product integration

Existing product integration

The framework supports the existing Olive product experiences rather than replacing them.

  • Olive Wallet as shared infrastructure
  • Connected DeFi access
  • Quantitative Investments research
  • Agentic Trading execution controls
  • Asset and Portfolio Management oversight
  • RWA marketplace claim discipline

Role-aware display and portfolio accounting must prevent double counting between underlying assets and representations. OCLV is excluded from Trade; OLV is trade-enabled only by admin control.

06 / More tokens

Additional token adoption

Extend the framework beyond the initial integration only after the adoption, custody and representation model is approved and proven.

  • Asset intake criteria
  • Legal and custody review
  • Technical integration standard
  • Issuance template and controls
  • Security review and disclosure

Additional integrations are not live until approved.

07 / Interoperability

Cross-chain interoperability

Cross-chain is a later roadmap capability. The CLV → OCLV asset bridge is live inside Olive. No cross-chain Olive bridge is live, and OCLV is not cross-chain.

  • Interoperability architecture
  • Network integration model
  • Message and value verification
  • Bridge risk assessment
  • Monitoring and incident response

No cross-chain representation claim is permitted before implementation, verification and disclosure.

08 / Ecosystem

Ecosystem expansion

Partners, integrations and developer surfaces follow the framework's approved asset and security model.

  • Partner standards
  • Integration documentation
  • Developer APIs
  • Ecosystem onboarding
  • Reporting and review

What is live now

The Olive app and wallet are live. CLV deposits work on Ethereum and BNB Smart Chain. CLV → OCLV is a 1:1 bridge. OCLV is not tradeable; OCLV → OLV is a fixed swap. OLV is tradeable only when admin enables Trade. Cross-chain interoperability and public custody attestation remain incomplete.
